- [x] 2.2 Implement `src/discovery/task-progress.ts` to derive task progress from tasks.md (checkbox regex, `x`/`X` complete, fenced code blocks ignored, `[P]` markers ignored, null when no counted line) and to derive change status from task progress (Draft, Not Started, In Progress, Complete). Verified by `test/discovery/task-progress.test.ts` asserting every row of the checkbox parsing table and the status table.
- [x] 2.3 Implement `src/discovery/metadata.ts` to report per-change metadata from a single read of `.openspec.yaml`: ISO `created` date or null, proposer display name from `created_by` (substring before `<`, trimmed, empty → null), plus the artifact list (`.md` files relative to the change directory, forward slashes, string-sorted) and the newest `.md` modification time. Verified by `test/discovery/metadata.test.ts` asserting every row of the creation metadata and proposer tables and the modification date example.
- [x] 2.4 Implement `src/discovery/scan.ts` exporting `scanChanges(projectRoot)` to scan changes from all three Spectra sources (Active from `openspec/changes/` minus `archive`, Archived from `openspec/changes/archive/`, Parked from `<gitdir>/spectra-app/changes/`), returns a `ScanSnapshot`, and degrade gracefully on unreadable changes by omitting the change and appending a warning naming its directory. Verified by `test/discovery/scan.test.ts` covering the mixed layout example, absent source directories, the `archive` exclusion, an unreadable directory (chmod 000), and a change without `.openspec.yaml`.
- [x] 2.5 Ensure the scan meets scan without blocking the caller: `scanChanges` uses only `fs/promises` and returns a promise immediately. Verified by a test asserting the return value is a Promise and by a lint rule (`no-restricted-imports` on `fs` sync functions) in the discovery directory.

## 3. Herdr adapter (three-layer module split: discovery, herdr adapter, tui — adapter layer)

- [x] 3.1 Implement `src/herdr/context.ts` to resolve the invocation context from the environment, which also implements resolve the project root from the workspace cwd (`HERDR_PLUGIN_CONTEXT_JSON.workspace.cwd` → else `process.cwd()`, stderr warning on unparsable JSON; `HERDR_PANE_ID` and `HERDR_BIN_PATH` → null when unset). Verified by `test/herdr/context.test.ts` asserting every row of the project root resolution table.
- [x] 3.2 Implement `src/herdr/client.ts` so the Herdr adapter executes the Herdr binary without a shell: `HerdrClient` interface, production `execFile` implementation, `sendTextToPane` (single argv element, no newline), and `openInEditorSplit` that follows the decision to open the editor in a split pane with two Herdr calls (`pane split --direction right --cwd <root>`, plus `--pane <paneId>` when known, parse `result.pane.pane_id` from the default JSON output, then `pane run <id> <editor> '<quoted path>'`). Failures return a result object, never throw; null binary path fails without spawning. Verified by `test/herdr/client.test.ts` with a fake spawner asserting argv arrays, the missing pane id case, and the null binary case.
- [x] 3.3 Implement `src/herdr/clipboard.ts` for the clipboard fallback through platform commands, per the design decision clipboard through platform commands (`pbcopy` on darwin; `wl-copy` then `xclip -selection clipboard` on linux; text written to stdin without trailing newline; failure result when none succeed). Verified by `test/herdr/clipboard.test.ts` with a fake spawner covering the darwin case and the linux no-tool case.

## 4. Pane TUI (three-layer module split: discovery, herdr adapter, tui — tui layer)

- [x] 4.1 Implement `src/tui/ChangeTree.tsx` and `src/tui/tree-model.ts` to display changes as a grouped tree: three group nodes with `(N)` counts, Active expanded by default, cursor starting on Active, Up/Down/k/j movement without wrapping, Right/l expand, Left/h collapse or move to parent, window of rows limited to terminal height scrolling to keep the cursor visible; and to show task progress on change nodes as `name (complete/total)` only when progress exists. Verified by `test/tui/ChangeTree.test.tsx` using ink-testing-library for the count rendering, cursor bounds, Left-to-parent, tall-tree scrolling, and the with/without-progress node text.
- [x] 4.2 Implement `src/tui/Preview.tsx` and the Enter handler so the user can preview an artifact inside the pane: Enter on an artifact reads the file and shows raw text with the relative path as title, Enter on a group or change toggles expansion, a missing file sets the status bar to `File not found: <relative path>` without changing the preview. Verified by `test/tui/App.test.tsx` cases for artifact preview, change toggle, and deleted file.
- [x] 4.3 Implement the `e` handler so the user can open an artifact in the editor through the adapter: editor from `EDITOR` or `vi`, status bar `Opened in <editor>` on success, `File not found: <relative path>` when missing, `Could not open editor` on adapter failure, no-op on group or change nodes. Verified by `test/tui/App.test.tsx` cases with a fake `HerdrClient` asserting the editor command and each status message.
- [x] 4.4 Implement `src/tui/StatusBar.tsx` and scan state handling in `src/tui/App.tsx` to indicate loading, empty, and warning states (`Scanning…` during a scan, the not-initialised message when `openspec/` is absent, `<N> change(s) skipped` when warnings exist) and to provide a Spectra changes pane that scans once on start and exits with code 0 on `q` or Escape. Verified by `test/tui/App.test.tsx` cases for each message and for the exit call on `q`.
- [x] 4.5 Implement the `R` handler to rescan on demand: new scan, tree rebuilt, expansion state preserved for nodes that still exist, cursor kept on the same node or moved to the group above it when the node is gone. Verified by `test/tui/App.test.tsx` cases with a fake scanner returning a different snapshot on the second call.
- [x] 4.6 Implement `src/tui/keymap.ts` and the command handlers to send a Spectra command for the selected change following the keymap for the core change and the decision to send the command to the invoking pane and never submit it: keys `d a i r c` map to the five commands in workflow order, command text is `<command> <name>`, the selected change is the node under the cursor or the artifact's owner, group nodes show `Select a change first`; with a pane id the adapter's `sendTextToPane` is called and the process exits 0 on success; without a pane id the clipboard receives the text and the status bar shows `Copied: <text>`; on send failure the clipboard receives the text and the status bar shows `Herdr send failed, copied instead`; on clipboard failure it shows `Copy failed: <text>`. No scan runs and expansion state is kept. Verified by `test/tui/App.test.tsx` cases asserting the command text table, the exit call, each fallback message, and that the fake scanner was not called again.
- [x] 4.7 Wire `src/pane.tsx` as the entry point: reads the invocation context, applies the rule that the project root falls back to the invoking pane's cwd via `pane get` when the context JSON has none (verified by `test/herdr/project-root.test.ts`), constructs the production `HerdrClient`, renders `App` with Ink. Verified by running `node dist/pane.js` in this repository and seeing the three groups with `herdr-spectra-pane-core` under Active with its task counts.
