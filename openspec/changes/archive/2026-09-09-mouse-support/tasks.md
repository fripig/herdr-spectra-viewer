## 2. Wiring in the pane

- [x] 2.1 Apply the decision that layout is computed by App and shared with the tree renderer: `App` builds a `Layout` from `treeTop`, `treeHeight`, `stdout.columns` (fallback 80) and the current `windowStart` and row count, and routes parsed mouse events through `hitTest` using the input path chosen in 1.1, so that a mouse report never reaches the Escape or command-key branches. Verified by `test/tui/App.test.tsx` case asserting that writing `ESC[<0;17;18M` to stdin does not call `onExit`, `sendText`, or `copy`.
- [x] 2.2 Implement the decision that click semantics mirror the keyboard so the user can select, toggle, and open by clicking the tree: label press moves the cursor, marker press toggles a group or change, artifact press calls the editor adapter through the existing `openEditor` path (missing file shows `File not found: <relative path>`), press below the last node or above the tree does nothing, releases ignored. Verified by `test/tui/App.test.tsx` cases for each of the six click scenarios, including the scrolled-window case with `treeTop` 1.
- [x] 2.3 Implement scroll with the mouse wheel: wheel over the tree calls the existing cursor move without wrapping; wheel on the status bar or header does nothing. Verified by `test/tui/App.test.tsx` cases for wheel-down moving one row, wheel-up at the first row staying put, and a wheel event on the status bar leaving the cursor unchanged.
- [x] 2.4 Apply the decision that the mouse reporting lifecycle lives in the pane entry point: `src/pane.tsx` writes `MOUSE_ENABLE` before `render` and a single `shutdown()` writes `MOUSE_DISABLE` from `onExit`, `waitUntilExit`, SIGINT, SIGTERM, and the `exit` event, so the pane continues to provide a Spectra changes pane that restores the terminal on every exit path. Verified by `test/tui/mouse-lifecycle.test.ts` asserting the writer receives the enable sequence on start and the disable sequence once per `shutdown()` call.
